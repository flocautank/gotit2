L’open source, un logiciel dont la recette est publique

Beaucoup de logiciels que vous utilisez sans le savoir sont « ouverts » : leur code est public. Ce que cela change, et ce que cela ne change pas.

Découverte5 min2 animations

Une recette de cuisine peut rester secrète, enfermée dans le coffre d’un restaurant ; ou être imprimée dans un livre, que chacun peut lire et refaire. Un logiciel, c’est pareil : sa recette s’appelle le code source. Quand elle est publique, on parle d’open source.

Scène 1 — Fermé, ou ouvert

Un logiciel est écrit dans un code.C’est la liste précise de ce que l’ordinateur doit faire.

Souvent, ce code est gardé secret.On utilise le logiciel sans jamais voir comment il est fait : il est dit propriétaire.

Parfois, il est publié.N’importe qui peut le lire, à côté de la licence qui dit ce qu’on a le droit d’en faire.

C’est ce qu’on appelle l’open source.Ouvert veut dire lisible, pas forcément sans règles : la licence fixe toujours le cadre.

L’analogie

La recette secrète du restaurant et la recette du livre de cuisine. Avec le livre, on peut vérifier qu’il n’y a rien de louche dans la sauce, corriger une erreur, ou inventer sa propre variante. Avec le coffre, on goûte et on fait confiance.

Ce que cela permet

Parce que le code est visible, plusieurs personnes peuvent le relire, signaler un défaut et proposer une amélioration.

Scène 2 — Une correction venue d’ailleurs

Quelqu’un lit le code.Un développeur, une entreprise, un chercheur : peu importe, il est ouvert.

Il y repère un défaut.Une erreur, ou une faille de sécurité que d’autres n’avaient pas vue.

Il propose une correction.Les responsables du projet la relisent avant de l’accepter.

Le code est corrigé.La modification entre dans le logiciel officiel.

Tous les utilisateurs en profitent.Une seule correction, partagée avec tous ceux qui utilisent le logiciel.

Ce que cela ne veut pas dire

Gratuit ? Pas forcément : le code est ouvert, mais l’installer, le faire tourner et le sécuriser demande du temps ou un prestataire, qui se paie. Sans règles ? Non plus : la licence précise ce qu’on peut faire, par exemple l’obligation de partager à son tour ses modifications. Plus sûr ? Pas automatiquement : un code que personne ne relit ne protège de rien. Ce qu’on gagne, c’est la possibilité de vérifier.

À retenir

  • Un logiciel open source publie son code source : chacun peut le lire.
  • Une licence dit ce qu’on a le droit d’en faire : ouvert ne veut pas dire sans règles.
  • Plusieurs paires d’yeux repèrent et corrigent les défauts, au profit de tous les utilisateurs.
  • Ouvert n’est pas synonyme de gratuit ni de sûr : c’est la possibilité de vérifier.
